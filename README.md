# 做个厨神 · 家庭烹饪博物馆

面向「想学做饭的人」的移动端高保真原型，馆藏 **100 道菜**（编号 No.01–No.100）。解决五件事：
**今天吃啥 → 家里缺什么 → 买什么菜 → 怎么一步步做 → 做的时候不懂就问 AI**。

产品定位是「烹饪执行陪伴工具」而非菜谱库 —— 详见 `PRODUCT_ANALYSIS.md`。

视觉语言：**博物馆标本图鉴风** —— 做旧纸底、墨线铜版插画、图鉴编号与拉丁学名、展签式排版、朱砂印章。每道菜都被当成一件藏品来著录。

> 风格演进：手绘厨房手帐 → 博物馆标本图鉴 → 清新果蔬风 → **回到博物馆标本图鉴（当前版本）**。

## 主链路

```
#/home      展厅：摇藏品柜抽今日展品
   ↓
#/recipe/:id  展签：藏品数据、风味谱、流派做法、材料表、工序
   ↓
#/shopping    采集清单：按科属分组勾选
   ↓
#/cook/:id    制作：全屏分步，耗时工序内嵌计时器
   ↓
#/me          研究员档案：口味、忌口、藏品、制作记录
```

## 页面

| 路由 | 页面 | 能做什么 |
|---|---|---|
| `#/home` | 展厅 | 摇藏品柜抽菜（按口味档案加权）、藏品卡（编号/科属/时令/产地/耗时）、常设陈列 |
| `#/recipe/:id` | 展品展签 | 铜版线稿大图、藏品数据、风味谱（咸甜酸鲜辣油）、流派做法切换、材料表（调料可问作用）、工序、影像档案 |
| `#/shopping` | 采集清单 | 按蔬菜/肉蛋/水产/调料分科属，勾选划线，手动补录 |
| `#/cook/:id` | 制作 | 全屏单步、圆环计时器、后台迷你计时条、随时问馆长 |
| `#/discover` | 文献检索 | 搜菜名→AI 调阅抖音/小红书影像→AI 拆解材料用量与工序→一键转清单 |
| `#/me` | 研究员档案 | 我的冰箱（勾选家里已有的食材）、口味档案、忌口登记、我的藏品、制作记录 |

AI 助手是全局浮层（馆长答疑），右下角按钮随时唤起，制作页内也有独立入口。

## 视觉系统要点

- **色**：做旧纸 `#F6F3EA`、墨 `#2A241E`；矿物色 —— 朱砂 `#8A3A2C` / 黄铜 `#95763A` / 鼠尾草绿 `#5C7364` / 赭石 / 石板蓝；卡片提白至 `#FFFDF8`，靠明度差让墨线浮出来
- **形**：几乎零圆角（`--pill` 为 2px）。双线展签框（`box-shadow` 多段实现）、虚线标本台、菱形分隔、编号铜牌、歪 4.5° 的朱砂印章、方形勾选框
- **字**：中文宋体 + 西文 Georgia；小标签统一西文大写 + `.16em` 宽字距（展签感）
- **插画**：内联 SVG 铜版线稿 —— 细墨线描边 + `feTurbulence` 抖动 + `url(#hatch)` 排线阴影；图鉴标注圆圈数字 + 虚线引线
- **质感**：纸面叠 SVG 噪点 `.026` + 23px 细网格 + 四角压暗；展柜外壳为浅胡桃木

## 关于 AI 层

`js/core/ai-mock.js` 暴露统一接口，全部用本地模拟（带延迟和流式打字）：

```js
AI.drawToday(prefs)               // 今日抽签
AI.recommend(name)                // 按菜名推荐做法
AI.findVideos(query, platforms)   // 影像检索（分两批返回）
AI.parseVideo(video)              // 命中馆藏则返回著录配料；没命中返回 matched:false
AI.ask(question, ctx, onChunk)    // 做菜中提问，流式返回
```

接真实模型时，只改这一个文件的函数体，视图层不用动。

### 关于「AI 拆解视频」

**这一版是诚实的，不假装。** 视频内容并没有被真正解析 —— 命中馆藏的菜，给的是本馆这道菜的著录数据，界面上明确写「来自本馆著录，不是从视频里提取」；没命中的直接说「这道菜不在本馆馆藏里」，引导去平台看原视频，**不编造一套通用配料模板**。

这么做的原因：界面暗示"AI 已经帮你拆好了"而实际是预置数据，是信任风险，真机上会被一眼识破。将来真接了视频理解，只需把 `parseVideo` 的实现换掉，视图层的诚实文案改成"已从视频中提取"即可。

## 关于计时器

- 用 **deadline 制**（记 `endsAt` 时间戳），页面切后台也不会走慢
- 支持**多个计时并行**，一个 250ms 的 tick 统一驱动
- 到点会响（WebAudio 合成蜂鸣，不需要音频文件）+ 震动 + 顶部提示
- 离开制作页后底部出现迷你计时条，点一下回到那一步
- 数据持久化，刷新页面后计时继续

## 关于厨房模式

制作页（`#/cook`）刻意**与浏览层风格分层**：

- 浏览层（展厅 / 展签 / 清单 / 档案）是博物馆纸感 —— 宋体、宽字距、低对比、有著录信息
- 执行层是深墨底 + 24px 大字号 + 暖金色强调 —— 厨房里手是湿的、有油、离屏幕远、光线杂，可读性优先于风格一致性

另外进制作页会尝试申请 **Wake Lock** 保持屏幕常亮，退出时释放。

## 关于冰箱与人数换算

- **我的冰箱**（档案页）：勾选家里现有的食材。勾上之后 —— 清单只补缺的（从加法变减法）、展品页显示「还差 N 样」、抽签优先推能立刻动手的菜（`ai-mock.js` 的 score 里加了冰箱加权）。
- **火星了也能接回来**：中途离开制作页，回来时若这道菜的计时器还没结束，会自动跳回那一步并显示「接着上次，从第 N 步继续」；计时器已结束或没有计时，则从头开始。判断依据是这道菜有没有没结束的计时器（`js/views/cook.js` 的 `runningStep`），不依赖退出按钮，从 tabbar 或路由跳走一样有效。
- **记录反哺**：做过的菜会降权，最近 3 次做过的再降一档，避免连着重复。
- **人数换算**：在档案页设几个人吃饭，展品页的用量会按 `人数 / 基准份量` 自动缩放（`D.scaleAmount`），加进清单的也是换算后的量。

## 已知边界

- 视频卡片是**搜索结果入口**，点击跳真实平台，不做内容抓取（见上「关于『AI 拆解视频』」）
- 100 道菜的插画复用 9 张铜版线稿（按食材形态就近匹配），并非每菜一图
- 只做 375×812 一种尺寸，不考虑响应式
- 字体走系统栈，不加载网络字体
- 数据存在 localStorage，换浏览器或清缓存会丢
