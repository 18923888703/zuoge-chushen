# 做个厨神 · 你的厨房搭子

面向「想学做饭的人」的移动端高保真原型，内置 **100 道菜**（编号 No.01–No.100）。解决五件事：
**今天吃啥 → 家里缺什么 → 买什么菜 → 怎么一步步做 → 做的时候不懂就问 AI**。

产品定位是「烹饪执行陪伴工具」而非菜谱库 —— 详见 `PRODUCT_ANALYSIS.md`。

视觉语言：**简约实拍风** —— 干净的灰白底、纯白卡片、细分割线、单一强调色、系统字体；每道菜配家常实拍照片，靠留白和层级建立秩序。

> 风格演进：手绘厨房手帐 → 博物馆标本图鉴 → 清新果蔬 → 厨房质感 → **简约实拍风（当前版本）**。

### 装到手机上（像正常 App 一样用）

本项目已做 **PWA 化**：手机浏览器打开上面的在线地址，即可「添加到主屏幕」当原生 App 用——

- **iOS**：Safari 打开 → 分享按钮 → **添加到主屏幕**；从桌面图标启动后全屏运行，无地址栏
- **Android**：Chrome 打开 → 菜单 → **添加到主屏幕 / 安装应用**

装好之后：

- 全屏 standalone 运行，自动适配刘海/灵动岛与底部 Home 条（safe-area）
- Service Worker 离线缓存：断网也能打开，二次进入秒开
- 手机浏览器里自动脱掉展柜外壳铺满整屏；桌面端保留外壳（原型展示态）
- **原生手感**：页面 push/pop 转场动画（`js/ui/nav.js`）、左边缘右滑返回（跟手、可取消）、Android 触感反馈
- 更新版本：改 `sw.js` 顶部的 `CACHE` 版本号（`chushen-v4` → `chushen-v5`）即可强制刷新缓存


## 主链路

```
#/home        下厨：没想好吃什么就抽一道（按口味与冰箱加权）
   ↓
#/recipe/:id  菜谱：实拍大图、耗时难度、备料情况、分步做法、换做法
   ↓
#/shopping    买菜清单：按蔬菜/肉蛋/水产/调料分组勾选
   ↓
#/cook/:id    下厨：全屏分步，耗时工序内嵌计时器
   ↓
#/me          档案：口味、忌口、冰箱、收藏、制作记录
```

## 页面

| 路由 | 页面 | 能做什么 |
|---|---|---|
| `#/home` | 下厨 | 抽一道今天吃的（按口味档案加权）、今日推荐卡、按你口味排的常做菜 |
| `#/recipe/:id` | 菜谱 | 实拍大图、备料/下锅/难度/份量、配料勾选（调料可问作用）、分步做法、换做法、看视频学 |
| `#/shopping` | 买菜清单 | 按蔬菜/肉蛋/水产/调料分组，勾选划线，手动补录 |
| `#/cook/:id` | 下厨模式 | 全屏单步、圆环计时器、后台迷你计时条、随时问厨房搭子 |
| `#/discover` | 搜视频 | 搜菜名→找抖音/小红书视频→命中菜谱的直接配齐配料→一键转清单 |
| `#/me` | 档案 | 我的冰箱（勾选家里已有的食材）、口味档案、忌口登记、收藏、制作记录 |

AI 助手是全局浮层（问厨房搭子），右下角按钮随时唤起，制作页内也有独立入口。

## 视觉系统要点

- **色**：底 `#FAFAF9`、卡片纯白、墨 `#1A1A18`；强调色只用一支 —— 柿红 `#C0563C`，辅助色全部低饱和退到背景
- **形**：8/11/14px 三档小圆角；卡片靠细线（`rgba(26,26,24,.08)`）和留白分层，几乎不用阴影
- **字**：系统无衬线一套到底（PingFang SC / Noto Sans CJK），字距收紧，层级靠字重和灰度
- **图片**：家常实拍菜品照（自然光、木桌、带锅气），底部压暗渐变托住标题文字
- **厨房模式**：深墨底 + 24px 大字号 + 金色强调，可读性优先

## 关于 AI 层

`js/core/ai-mock.js` 暴露统一接口，全部用本地模拟（带延迟和流式打字）：

```js
AI.drawToday(prefs)               // 今日抽签
AI.recommend(name)                // 按菜名推荐做法
AI.findVideos(query, platforms)   // 视频检索（分两批返回）
AI.parseVideo(video)              // 命中菜谱则返回配料；没命中返回 matched:false
AI.ask(question, ctx, onChunk)    // 做菜中提问，流式返回
```

接真实模型时，只改这一个文件的函数体，视图层不用动。

### 关于「配齐这道菜」

**这一版是诚实的，不假装。** 视频内容并没有被真正解析 —— 命中菜谱的菜，给的是这道菜在菜谱里的数据，界面上明确写「配料来自菜谱数据，不是从视频里提取」；没命中的直接说「这道菜不在现有菜谱里」，引导去平台看原视频，**不编造一套通用配料模板**。

这么做的原因：界面暗示"AI 已经帮你拆好了"而实际是预置数据，是信任风险，真机上会被一眼识破。将来真接了视频理解，只需把 `parseVideo` 的实现换掉，视图层的诚实文案改成"已从视频中提取"即可。

## 关于计时器

- 用 **deadline 制**（记 `endsAt` 时间戳），页面切后台也不会走慢
- 支持**多个计时并行**，一个 250ms 的 tick 统一驱动
- 到点会响（WebAudio 合成蜂鸣，不需要音频文件）+ 震动 + 顶部提示
- 离开制作页后底部出现迷你计时条，点一下回到那一步
- 数据持久化，刷新页面后计时继续

## 关于厨房模式

制作页（`#/cook`）刻意**与浏览层风格分层**：

- 浏览层（下厨 / 菜谱 / 清单 / 档案）是简约灰白 —— 明亮、留白、适合慢慢挑
- 执行层是深墨底 + 24px 大字号 + 暖金色强调 —— 厨房里手是湿的、有油、离屏幕远、光线杂，可读性优先于风格一致性

另外进制作页会尝试申请 **Wake Lock** 保持屏幕常亮，退出时释放。

## 关于冰箱与人数换算

- **我的冰箱**（档案页）：勾选家里现有的食材。勾上之后 —— 清单只补缺的（从加法变减法）、菜谱页显示「还差 N 样」、抽签优先推能立刻动手的菜（`ai-mock.js` 的 score 里加了冰箱加权）。
- **中途离开也能接回来**：离开制作页，回来时若这道菜的计时器还没结束，会自动跳回那一步并显示「接着上次，从第 N 步继续」；计时器已结束或没有计时，则从头开始。判断依据是这道菜有没有没结束的计时器（`js/views/cook.js` 的 `runningStep`），不依赖退出按钮，从 tabbar 或路由跳走一样有效。
- **记录反哺**：做过的菜会降权，最近 3 次做过的再降一档，避免连着重复。
- **人数换算**：在档案页设几个人吃饭，菜谱页的用量会按 `人数 / 基准份量` 自动缩放（`D.scaleAmount`），加进清单的也是换算后的量。

## 已知边界

- 视频卡片是**搜索结果入口**，点击跳真实平台，不做内容抓取（见上「关于『配齐这道菜』」）
- 100 道菜共用 17 张实拍图（按主食材就近匹配），并非每菜一图；接真实菜谱库时在 `js/data/photos.js` 换成每道菜自己的图即可
- 只做 390×844 手机尺寸优先，桌面保留外壳展示态
- 字体走系统栈，不加载网络字体
- 数据存在 localStorage，换浏览器或清缓存会丢
